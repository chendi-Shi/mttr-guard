# 2026-09-29 本机下游故障安全演练

**结果：一次真实监控链路的负向演练安全转人工，没有建议或执行回退。** 本机 checkout 的 5% 灰度请求调用 inventory 时得到真实 HTTP 503，checkout 返回 500；稳定组保持正常。Prometheus/Alertmanager 告警进入独立 API，取证 worker 读到指标、发布记录和父子关联的 OpenTelemetry span。三个分析角色分别识别错误率上升、下游失败和近期变更；反证角色 `veto`，事件进入 `NEEDS_ATTENTION`，`recommendation=null`。发布记录只有基线 r41 和故障注入 r43，没有回退动作。

[机器可读摘要、原始文件哈希和审计结果](2026-09-29-downstream.json)。原始监控响应、span、数据库及凭据只保存在本机忽略目录 `artifacts/local-pilot-20260929-downstream-02`。

## 做了什么、怎么做、解决什么问题

| 做了什么 | 怎么做 | 解决什么问题 |
| --- | --- | --- |
| 加入下游故障注入 | 新增本机 r43 场景：只让灰度 checkout 的 inventory HTTP 请求返回 503，并记录 `inventory.lookup` 错误 span | 验证“错误率上升且恰逢发布”时，系统仍能依据下游证据否决误回退 |
| 修复持久连接错误响应处理 | inventory 返回非 200 时也完整读取响应体，下一次复用连接前清空前一次响应 | 首次演练发现 503 响应体残留使稳定组随后错误，导致告警被抑制；修复后稳定组保持健康 |
| 给负向试点设定成功条件 | 预先要求事件为 `NEEDS_ATTENTION`、无回退建议、发布记录仅 r41 → r43，且审计校验通过 | 防止把“没触发告警”或“脚本报错”误记为安全转人工 |
| 保留失败与成功两次记录 | 第一次超时及稳定组错误、第二次转人工都写入机器可读摘要 | 暴露测试环境缺陷，不筛除失败尝试 |

## 实测证据

| 检查点 | 结果 |
| --- | --- |
| 故障前 | 只读数据源预检和固定基线门通过 |
| 故障后 | 灰度错误率 51.38%，稳定组 0%；灰度约 55 次/30 秒，稳定组约 1,090 次/30 秒 |
| 调用链 | `downstream_healthy=false`，失败点不在 `checkout.validate`；33 个失败 inventory span 均可关联父 checkout span，稳定组失败 checkout span 为 0 |
| 决策 | metrics=`regression`、traces=`downstream_failure`、changes=`recent_change`、critic=`veto`；无回退建议 |
| 发布与审计 | 发布记录 r41 → r43，没有 r41 回退；11 个原始工件哈希核对通过，17 条 HMAC 审计记录通过，结束时待处理任务 0 |
| 耗时 | 告警 `startsAt` 到分析就绪 7.178 秒；没有恢复确认或可报告的 MTTR |

第一次演练的稳定组也出现 175 次 HTTP 500，告警规则要求稳定组错误率 <1%，因此没有投递事件并在注入后超时。排查真实 span 发现：下游非 200 响应体未被读取，同一连接下一次稳定组请求被污染。修复并新增“灰度失败后稳定组仍正常”的测试后，第二次演练得到上述结果。**第一次是失败记录，不计入成功。**

本试点仍是同主机、合成流量和确定性分析角色的 `LOCAL_LAB`，只证明这一类下游故障在一次真实链路中被安全否决。尚缺证据缺失、重复告警、worker 重启等预登记演练，也没有企业证据源、企业 IAM/发布平台联调、多机高可用或 MTTR 对照数据。不能据此称生产级别。
